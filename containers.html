🎯 1. Introduzione ai Container

Cos'è un Container?

Un container è un'unità standard di software che impacchetta il codice e tutte le sue dipendenze in modo che l'applicazione funzioni in modo rapido e affidabile in diversi ambienti di computing.

🔑 Punti Chiave

  • Isolamento: I container isolano le applicazioni l'una dall'altra e dall'infrastruttura sottostante
  • Portabilità: Funzionano consistentemente su qualsiasi infrastruttura
  • Leggerezza: Condividono il kernel del sistema operativo, richiedendo meno risorse delle VM
  • Velocità: Avvio e arresto in pochi secondi

Container vs Virtual Machines

Virtual Machines (VM):

  • Include un sistema operativo completo
  • Maggiore isolamento ma più pesante
  • Avvio in minuti
  • Dimensione: GB

Containers:

  • Condividono il kernel dell'host
  • Leggeri e veloci
  • Avvio in secondi
  • Dimensione: MB

🐳 2. Docker: Fondamenti

Architettura Docker

Docker utilizza un'architettura client-server. Il Docker client comunica con il Docker daemon, che si occupa di costruire, eseguire e distribuire i container.

Componenti Principali

  • Docker Engine: Runtime che esegue i container
  • Docker Images: Template read-only per creare container
  • Docker Containers: Istanze in esecuzione delle immagini
  • Docker Registry: Repository per le immagini (es. Docker Hub)

Comandi Base

# Eseguire un container
docker run -d -p 80:80 nginx

# Listare container in esecuzione
docker ps

# Listare tutte le immagini
docker images

# Fermare un container
docker stop <container_id>

# Rimuovere un container
docker rm <container_id>

💡 Suggerimento: Usa docker run --rm per rimuovere automaticamente il container quando si ferma.

📦 3. Immagini e Dockerfile

Cosa sono le Immagini Docker?

Le immagini Docker sono template read-only che contengono un set di istruzioni per creare un container. Sono costruite usando un Dockerfile.

Struttura di un Dockerfile

# Immagine base
FROM node:18-alpine

# Directory di lavoro
WORKDIR /app

# Copia dipendenze
COPY package*.json ./
RUN npm install

# Copia codice sorgente
COPY . .

# Espone porta
EXPOSE 3000

# Comando di avvio
CMD ["node", "server.js"]

Istruzioni Principali

  • FROM: Specifica l'immagine base
  • WORKDIR: Imposta la directory di lavoro
  • COPY/ADD: Copia file nell'immagine
  • RUN: Esegue comandi durante il build
  • EXPOSE: Documenta le porte utilizzate
  • CMD/ENTRYPOINT: Comando di default all'avvio

Layer e Caching

Docker costruisce le immagini in layer. Ogni istruzione nel Dockerfile crea un nuovo layer. I layer sono cachati per velocizzare i build successivi.

🎯 Best Practice per Dockerfile

  • Ordina le istruzioni dalla meno alla più frequentemente modificata
  • Usa immagini base leggere (alpine)
  • Minimizza il numero di layer
  • Usa .dockerignore per escludere file non necessari

🌐 4. Networking nei Container

Tipi di Network

1. Bridge Network (default)

  • Network privato su un singolo host
  • I container possono comunicare tra loro
  • Isolamento dalla rete host

2. Host Network

  • Il container usa direttamente la rete dell'host
  • Nessun isolamento di rete
  • Migliori performance

3. Overlay Network

  • Connette container su host diversi
  • Usato in Docker Swarm

Port Mapping

# Mappa la porta 8080 dell'host alla porta 80 del container
docker run -p 8080:80 nginx

# Pubblica tutte le porte esposte
docker run -P nginx

Gestione Network

# Crea una rete custom
docker network create my-network

# Esegui container sulla rete custom
docker run --network my-network nginx

# Lista delle reti
docker network ls

💾 5. Volumi e Persistenza

Perché usare i Volumi?

I dati all'interno di un container sono effimeri: quando il container viene rimosso, i dati vengono persi. I volumi permettono la persistenza dei dati.

Tipi di Volumi

1. Named Volumes

  • Gestiti da Docker
  • Indipendenti dal filesystem dell'host
  • Raccomandati per la persistenza
# Crea un volume
docker volume create my-data

# Usa il volume
docker run -v my-data:/data nginx

2. Bind Mounts

  • Mappa una directory dell'host nel container
  • Utile per lo sviluppo
  • Dipendente dal filesystem dell'host
# Bind mount di una directory locale
docker run -v /path/on/host:/path/in/container nginx

⚠️ Attenzione: I bind mount possono avere implicazioni di sicurezza. Usa sempre path assoluti.

⚙️ 6. Orchestrazione

Docker Compose

Docker Compose è uno strumento per definire ed eseguire applicazioni Docker multi-container.

Esempio docker-compose.yml

version: '3.8'

services:
  web:
    build: .
    ports:
      - "8000:8000"
    volumes:
      - ./code:/app
    depends_on:
      - db

  db:
    image: postgres:15
    environment:
      POSTGRES_PASSWORD: password
    volumes:
      - db-data:/var/lib/postgresql/data

volumes:
  db-data:

Comandi Docker Compose

# Avvia i servizi
docker-compose up -d

# Ferma i servizi
docker-compose down

# Visualizza i log
docker-compose logs -f

# Scala un servizio
docker-compose up -d --scale web=3

Kubernetes

Per deployment su larga scala, Kubernetes è il sistema di orchestrazione più utilizzato:

  • Gestione automatica dei container
  • Self-healing e auto-scaling
  • Service discovery e load balancing
  • Rolling updates e rollback

✅ 7. Best Practices

🔐 Sicurezza

  • Non eseguire mai container come root quando possibile
  • Scansiona le immagini per vulnerabilità
  • Usa immagini ufficiali e verificate
  • Mantieni aggiornate le immagini base
  • Non includere segreti nelle immagini

⚡ Performance

  • Minimizza le dimensioni delle immagini
  • Usa multi-stage builds
  • Ottimizza il layer caching
  • Imposta limiti di risorse appropriate

🏗️ Sviluppo

  • Un processo per container
  • Usa variabili d'ambiente per la configurazione
  • Implementa health checks
  • Logga su stdout/stderr
  • Rendi i container stateless quando possibile

Multi-Stage Build Example

# Stage 1: Build
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production
FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY package*.json ./
RUN npm ci --production
CMD ["node", "dist/server.js"]

💡 Risultato: Immagine finale molto più piccola, contenente solo i file necessari per l'esecuzione.
